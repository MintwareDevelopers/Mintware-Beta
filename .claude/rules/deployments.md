# Deployments and runtime configuration

## Status

The web application is deployed on Vercel. Current liquidity and Earn contracts are testnet-only and unaudited;
external audit gates real value. Address truth is [`config/deployments.json`](../../config/deployments.json).

## Current MarketEngine configuration

The V1 MarketEngine integration uses these server-only settings (set on Vercel production):

| Variable | Use |
|---|---|
| `MARKET_ENGINE_INSTANCES` | Configured engine instances / registry fallback configuration. |
| `MARKET_ENGINE_CHAIN_ID` | Chain served by the MarketEngine API. |
| `MARKET_ENGINE_RPC_URL` | Read-only chain RPC for MarketEngine verification and reads. |
| `MARKET_ENGINE_OWNER` | Expected owner during instance verification. |
| `MARKET_ENGINE_QUOTE_ASSET` | Expected quote token during instance verification. |
| `MARKET_ENGINE_CODEHASHES` | Allowed runtime code hashes for verification. |

The old `LP_GATEWAY_*` configuration for PositionManager/Staging, operator deploy/harvest, yield-source routing,
ledger, or portfolio mechanics is retired. Remaining environment reads are `LP_GATEWAY_GT_NETWORK`,
`LP_GATEWAY_DISCOVER_USDG` (fallback `LP_GATEWAY_USDG`), `LP_GATEWAY_DISCOVER_PRUNE_GRACE_HOURS`,
`LP_GATEWAY_CURATORS`, and the legacy server-to-server `LP_GATEWAY_CURATOR_SECRET`. These serve Discover
network/quote selection, pruning, curator wallet allowlisting, and its bearer fallback. `RWA_DEMO_OPERATORS`
also falls back to `LP_GATEWAY_CURATORS`.

## Other runtime settings

- `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` configure browser Supabase access;
  `SUPABASE_SERVICE_ROLE_KEY` is server-only.
- `PRIVY_APP_ID` / `PRIVY_APP_SECRET` configure wallet and server session integration.
- `V2_PASSWORD` gates guarded `/app` workspaces; it does not change on-chain deployment status.
- `ADMIN_SECRET` protects admin diagnostic routes.
- `EDGE_AUTH_URL` / `EDGE_AUTH_SECRET` configure the edge-auth service where referenced. They do not enable a
  MarketEngine operator lifecycle or card merchant settlement.

## Deployment record

A deployed address belongs in [`config/deployments.json`](../../config/deployments.json). Record full addresses only
when supported by a broadcast or an on-chain read; `eth_getCode` confirms code presence, not constructor state or
product readiness. Do not treat a source file as proof of deployment.
